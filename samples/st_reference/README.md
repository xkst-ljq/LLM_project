# SillyTavern 参考卡样本

放置真实的 ST 角色卡，供**阶段 3「UI 生成」**设计识别层时对照。

## 为什么要留在仓库里

识别层要从原卡的 HTML/CSS 反推「作者想表达什么界面」。
凭空假设会有两类典型失败：

- **误判**：把普通排版（`<i>斜体</i>` 之类）当成 UI 组件，硬生成一堆没用的东西；
- **漏判**：真正的状态面板因写法不在预期内，被当成普通文本跳过。

用户明确要求「**原版就没有的当然就不去设计**」——
要守住这条，就得先知道「有」长什么样。

样本同时充当**转译回归用例**：改了识别或生成逻辑后，
拿这里的卡重跑一遍，看产物有没有退化。

## 放什么

- `*.json` —— 角色卡 JSON（ST 导出，或从 PNG 的 tEXt 块解出来）
- `*.png` —— 原始 PNG 卡（数据嵌在 `chara` / `ccv3` 文本块里）

两种都行。工具的 `png_chara_reader.dart` 支持 tEXt / zTXt / iTXt，
优先读 `ccv3`，回落 `chara`。

## 关注的字段

| 字段 | 看什么 |
|---|---|
| `description` | 有没有 `<div style="...">` 这类样式块（设定，一直生效） |
| `first_mes` | 开场消息里的界面元素（只出现一次） |
| `mes_example` | 示例对话里的格式模板 |

## 隐私

只需要**结构**不需要正文。若卡里有不便公开的设定，
删掉文本只留 HTML 骨架即可，不影响识别层设计。
