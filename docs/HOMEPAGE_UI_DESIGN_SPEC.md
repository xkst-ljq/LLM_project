# LLM Project 主页 UI 设计说明

> **版本：Homepage UI Spec v1.0**  
> **状态：视觉与交互说明**  
> **参考原型：** `prototypes/home_ui/index.html`、`prototypes/home_ui/new_user.html`  
> **适用范围：** 主页体验舞台、当前角色入口、角色选择、Avatar Stage、模块轨道、新用户状态

---

## 0. 这份设计解决什么问题

当前项目不是普通的功能型 App，也不是 Agent 控制台。

主页的职责是：

> **让用户进入一个角色体验，而不是让用户先浏览一列功能。**

因此主页采用“舞台 + 入口 + 模块”的结构：

```text
角色体验舞台
    ├── 当前角色入口色面
    ├── Avatar Stage
    └── 体验氛围

功能轨道
    ├── 角色库
    ├── 世界书库
    ├── 背景图库
    └── UI 模组库
```

页面中的每个位置都有明确职责：

- 当前角色色面：进入或切换当前角色。
- Avatar Stage：未来 Live2D / 3D 角色存在的位置。
- Modules：进入创作和资产管理页面。
- 右侧边缘：设置侧滑入口。

主页不承担体验模式、体验档案等尚未完成设计的入口。

## 1. 设计来源与演变

### 1.1 原始问题

早期主页是多个 `ListTile` 从上到下排列：

```text
聊天
角色库
世界书库
背景图库
UI 模组库
```

它能工作，但有三个问题：

1. 所有功能权重相同，用户不知道下一步该做什么。
2. 主页没有角色体验的中心。
3. 未来 Live2D / 3D 模型没有自然的放置位置。

### 1.2 当前空间构图

最终构图保留了原主页的四个功能入口，但改变了它们的空间关系：

```text
左上：当前角色入口色面
左下：未来角色舞台
右下：功能模块轨道
全局：斜向几何背景
```

它不是把功能删掉，而是把“体验”放在前景，把“管理”放到侧边。

### 1.3 HTML 原型的作用

HTML 不是最终实现代码，而是视觉和交互的参考基准：

```text
index.html
  有角色 / 正常体验状态

new_user.html
  没有角色 / 第一次使用状态
```

HTML 中的颜色、比例、斜切形状、动画时间和交互流程都属于设计参考；Flutter 实现可以使用不同的技术，但不能破坏这些语义关系。

## 2. 整体画面结构

### 2.1 设备画布

HTML 通过 `.device` 模拟移动端设备：

- 移动端：占满屏幕，使用安全区。
- 桌面预览：限制在手机比例中，方便观察移动端构图。
- 页面本身禁止横向溢出。
- 主页的功能不是通过横屏分栏表达，而是通过上下和左右的空间错位表达。

Flutter 对应：

```text
HomeExperiencePage
└── LayoutBuilder
    └── Stack
```

主页使用 `Stack` 是因为 Avatar Stage、角色入口和模块轨道需要独立定位，而不是组成普通纵向列表。

### 2.2 画布比例

基础比例来自 HTML 原型：

```text
角色入口宽度       画布宽度的约 76%
角色入口高度       约 166 logical pixels
模块轨道宽度       画布宽度的约 45%
Avatar Stage        占据剩余左下空间
```

这些比例可以随屏幕宽度变化，但不能依赖固定的桌面像素。

### 2.3 页面层级

从底到顶：

```text
1. 主题背景
2. 几何背景线 / 椭圆轨道
3. Avatar Stage
4. 当前角色入口色面
5. ModuleRail
6. 右侧设置侧滑
7. 角色选择局部蒙版
8. Toast / 提示
```

角色选择层只覆盖角色移动的那一行，不应该把整页变成一个深色弹窗。

## 3. Day / Night 基础主题

### 3.1 Day

Day 模式参考 HTML 的浅色原型：

- 画布：暖白或浅灰白。
- 几何线：低透明度灰蓝色。
- 角色色面：靛蓝、蓝紫。
- Avatar Stage：低饱和青绿色。
- 功能模块：保留少量不同的模块强调色。
- 遮罩：非常浅，只用于局部选择状态。

Day 的目标是：

> **像一张有几何标记的角色体验纸面。**

### 3.2 Night

Night 模式参考 HTML 的沉浸版本：

- 画布：蓝黑色，不使用纯黑。
- 几何线：低亮度灰蓝色。
- 角色封面：增强暗部遮罩。
- Avatar Stage：青绿色光晕可略微增强。
- 模块表面：深色半透明。
- 遮罩：比 Day 稍明显，但仍然只覆盖局部区域。

Night 的目标是：

> **像角色进入前的夜间舞台，而不是通用黑色后台。**

### 3.3 主题 Token

Flutter 使用 `ThemeExtension<AppThemeTokens>`，主页不直接散落颜色。

主页重点使用：

```text
canvas
canvasDeep
surface
surfaceElevated
textPrimary
textSecondary
textMuted
accent
accentStrong
stage
scrim
shadow
outline
```

角色封面可以覆盖背景表现，但不能覆盖文字对比度和系统语义色。

## 4. 左上角品牌标识

### 4.1 视觉来源

HTML 顶部使用：

```text
菱形状态灯 + LLM PROJECT
```

它来自“项目正在运行 / 当前体验引擎已准备好”的概念，而不是传统 AppBar 标题。

### 4.2 状态灯

状态灯不是装饰图标，而是一个低频运行状态信号：

- 几何形状：小型旋转方块。
- 颜色：当前主题强调色。
- 动画周期：约 4.2 秒。
- 动画范围：只改变透明度和光晕，不改变布局尺寸。

推荐状态语义：

```text
正常       强调色呼吸
加载       暖色 / 低频变化
错误       红色静态或慢速脉冲
关闭       低透明度灰色
```

当前原型只实现“正常”状态。后续不应该让状态灯变成高频闪烁提示。

### 4.3 Flutter 对应

```text
_BrandMark
```

它应该是独立小组件，不能和主页数据加载逻辑绑在一起。

## 5. 主题切换按钮

### 5.1 位置

主题按钮位于右上角，但这里只放主题切换，不放“更多设置”。

原因：

- Day / Night 是即时的全局显示偏好；
- 设置属于后台能力，已有右侧侧滑入口；
- 避免右上角堆叠多个系统按钮。

### 5.2 行为

点击后：

```text
Day ↔ Night
```

主题切换使用约 240ms 的颜色和表面过渡，不重新播放主页入场动画。

### 5.3 Flutter 对应

```text
AppThemeManager
ThemeData.day
ThemeData.night
ThemeExtension<AppThemeTokens>
```

主题切换后只更新主题，不应该让主页重新执行角色、模块、舞台的入场动画。

## 6. 当前角色入口色面

这是主页最重要的组件。

### 6.1 功能职责

当前角色入口色面同时承载：

- 当前角色封面；
- 当前角色名称；
- 当前角色身份 / 场景信息；
- 点击封面打开最近角色选择；
- 点击右下角箭头进入聊天。

它不是普通 `CharacterCard` 的列表卡片，而是：

> **Current Role Entry Surface / 当前角色入口色面**

数据模型仍然可以使用 `CharacterCard`，但 UI 组件不应命名为普通卡片列表。

### 6.2 形状

HTML 使用斜切几何形状：

```text
左上角基本保持直角
右上和右下形成倾斜切面
左下轻微收斜
```

Flutter 使用：

```text
_SlantedSurfaceClipper
```

形状的意义是：

- 给角色入口一个方向性；
- 让箭头和进入动作有空间指向；
- 与右下模块的几何面形成统一语言。

### 6.3 封面背景

有真实 `cardImagePath` 时：

```text
角色卡封面 → BoxFit.cover
```

封面上叠加：

- 靛蓝 / 角色强调色渐变；
- 左侧较深的文字保护层；
- 右侧较轻的图像保留区；
- 几何环形装饰。

没有封面时：

- 使用 Day / Night 的主题渐变；
- 不显示假的角色图片；
- 仍保留角色入口的几何结构。

### 6.4 文本层级

角色色面内部的文本顺序：

```text
顶部左侧：CURRENT ROLE / FIRST EXPERIENCE
中上部：角色名称
底部：角色描述或距上次聊天时间
右下角：进入箭头
```

角色名称不能被放在卡片中央之外，也不能让描述挤压进入按钮的命中区。

### 6.5 两个点击区域

```text
封面区域       打开最近角色色面选择
进入箭头       进入 ChatPage
```

点击封面不能直接进入聊天。

空状态时：

```text
点击整个空角色色面 → CharacterLibraryPage
```

### 6.6 入口动画

点击进入箭头时：

```text
角色色面向外扩张
→ 当前角色身份保留
→ Avatar Stage 淡出
→ ChatPage / Scene UI 进入
```

点击封面打开角色选择时，不播放进入聊天动画。

## 7. Avatar Stage

### 7.1 来历

左下方的留白不是未完成区域，而是为未来 Live2D / 3D 角色保留的舞台。

它的存在目的：

- 保持主页拥有角色存在感；
- 不提前伪造角色内容；
- 让模型可以在后续直接接入，不需要重新设计主页布局。

### 7.2 当前空舞台

在没有 Live2D / 3D 时，只显示：

- 舞台光晕；
- 椭圆轨道；
- 低透明度几何线；
- `AVATAR STAGE · RESERVED` 或新用户提示。

不要显示一块明显的“占位框”，也不要用大段说明填满留白。

### 7.3 呼吸动画

当前 Flutter Agent 版本使用两组动画：

```text
光晕       6 秒往返
轨道       9 秒往返
```

动画应该：

- 低频；
- 低幅；
- 不改变舞台布局；
- 不抢角色入口和模块轨道的焦点。

未来接入模型后：

```text
AvatarStage
└── AvatarHost
    ├── Live2D
    └── 3D Model
```

舞台光晕可以继续保留，但模型待机动画由 AvatarHost 管理。

## 8. ModuleRail 功能轨道

### 8.1 来源

主页右下区域保留原主页功能，但不再使用一列等权重的菜单。

当前模块固定为四个：

```text
角色库
世界书库
背景图库
UI 模组库
```

体验模式和体验档案暂时不加入，因为对应功能还没有完成独立设计。

### 8.2 模块结构

每个模块由两层组成：

```text
顶部：图标 + 标题 + 进入箭头
底部：内部简短预览
```

### 8.3 模块预览

#### 角色库

```text
人物轮廓图标 + 人物数量
```

数量语义是角色数量，不显示虚构的最近消息。

#### 世界书库

```text
短设定线条 + 世界书数量
```

必须显示：

```text
N 种世界书
```

而不是：

```text
N 条设定
```

因为第一层对象是世界书，而不是世界书条目。

#### 背景图库

```text
单色图片框图标 + 背景数量
```

图片预览图标使用统一的模块强调色，不使用多个彩色方块。

#### UI 模组库

```text
SCENE / OPENING 等能力标签 + 模组数量
```

### 8.4 滚动

ModuleRail 使用正常垂直滚动：

- 用户预期明确；
- 支持未来继续增加模块；
- 不与右侧设置水平侧滑冲突；
- 斜切和颜色只用于视觉，不改变滚动轴。

### 8.5 动画

模块只使用：

- 首次进入错峰动画；
- 点击按压反馈；
- 当前模块轻微强调；
- 滚动时的自然物理反馈。

不使用每个模块持续漂浮或独立呼吸。

### 8.6 Flutter 对应

```text
_ModulePreviewTile
_ModulePreviewVisual
_PreviewGlyph
```

模块卡必须有有限高度约束。`Column` 内不能使用依赖无限高度的 `Spacer` 或 `Expanded`。

## 9. 右侧设置入口

### 9.1 不是主页可见组件

设置不是主页的视觉主体，因此不作为一个额外功能色块加入 ModuleRail，也不使用固定“更多”按钮替代已有手势。

### 9.2 现有交互

保留项目已有的整页侧滑：

```text
从右侧边缘开始拖动
→ 主页舞台整体移动
→ 右侧设置页出现
```

这部分属于已有能力，主页重构只做回归验证，不重新设计成普通抽屉。

### 9.3 设置面板职责

设置页继续承载：

- API 配置；
- 用户设定；
- Prompt 策略；
- 备份与恢复；
- 教程与导览；
- UI 创作工作室。

它属于后台空间，不应遮挡角色舞台。

## 10. 角色选择层

### 10.1 打开方式

```text
点击当前角色封面
```

不跳转页面，不打开普通 Dialog。

### 10.2 局部蒙版

蒙版只覆盖角色色面移动的那一行：

- 颜色很浅；
- 上下有渐变过渡；
- 不压暗整个 Avatar Stage；
- 不覆盖整个主页；
- 点击蒙版外部取消。

### 10.3 色面轨道

角色的选择项仍然是同一种不规则角色色面：

```text
选中色面：与主页角色入口等大
预备色面：按比例缩小
排列方向：从左到右
初始顺序：最新聊天 → 更早聊天
```

选择旧角色时：

```text
第一次点击：聚焦，移动到主页角色槽位
第二次点击：确认，替换主页当前角色
```

选择层中不显示聊天进入箭头。

### 10.4 与角色库的边界

角色色面轨道只显示最近体验角色。

“全部角色库”属于角色库页面，不能把完整角色管理能力塞进选择层。

## 11. 新用户状态

参考文件：

```text
prototypes/home_ui/new_user.html
```

### 11.1 没有角色时

角色入口显示：

```text
FIRST EXPERIENCE
开始第一次体验
从角色库导入或创建一个角色
```

### 11.2 Avatar Stage

显示：

```text
YOUR STAGE
等待第一个角色登场
```

保留空舞台，不创建假的当前角色。

### 11.3 角色库引导

右下角色库模块承担“从这里开始”的提示：

- 首次出现一次轻微强调；
- 显示导入 / 创建方向；
- 点击后进入真实 `CharacterLibraryPage`。

### 11.4 新用户不显示

- 继续聊天；
- 最近角色；
- 虚构的聊天时间；
- 空的角色选择轨道。

## 12. 数据与页面职责

### 12.1 HomeExperiencePage

负责：

- 展示主页状态；
- 读取并呈现角色快照；
- 处理主页入口交互；
- 处理模块跳转；
- 驱动主页动画。

### 12.2 DatabaseService

负责：

- 读取角色；
- 读取最近消息时间；
- 读取世界书；
- 提供聚合查询。

它不负责决定页面视觉状态。

### 12.3 ChatPage

负责：

- 当前聊天会话；
- 消息；
- scene / opening / extra_sticky；
- 聊天页内的角色切换；
- 进入聊天后的运行时体验。

主页和聊天页需要统一当前角色来源，不能长期分别使用不同的“当前角色”判定。

## 13. 当前动画参数参考

| 动画 | 时长 / 周期 | 用途 |
| --- | ---: | --- |
| 品牌状态灯 | 4.2 秒 | 项目运行状态呼吸 |
| Avatar 光晕 | 6 秒 | 舞台呼吸 |
| Avatar 轨道 | 9 秒 | 低幅轨道变化 |
| 封面呼吸 | 16 秒 | 角色封面轻微位移 |
| 主页入场 | 约 900ms | 按层级组装主页 |
| 模块错峰 | 约 300～600ms | 模块依次出现 |
| 进入聊天 | 约 520ms | 角色色面进入聊天舞台 |
| 设置侧滑 | 跟手 | 现有整页侧移 |

所有动画都必须支持减少动效设置。

## 14. 视觉禁区

主页后续不能出现以下回退：

- 恢复成多个等宽 `ListTile` 纵向菜单；
- 给角色选择层再增加一个大背景色块；
- 用普通圆角卡片替代不规则角色色面；
- 把设置固定成右上角“更多”；
- 把体验模式和体验档案提前塞入模块轨道；
- 用多色圆点代替语义化的人物 / 图片预览图标；
- 用全屏深色蒙版遮住 Avatar Stage；
- 角色选择后重新播放整套主页入场动画；
- 在模块预览卡的无限高度 Column 中使用 `Spacer` / `Expanded`。

## 16. 最终定位

主页最终不是一个管理菜单，而是：

> **一个有当前角色、有空的模型舞台、有功能轨道，并且可以随时进入角色体验的移动端游戏主页。**

它的视觉可以变化，但空间职责不能变化：

```text
角色在前
舞台在后
功能在侧
设置在后台
```
